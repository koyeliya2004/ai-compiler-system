How it works
A compiler, not a chatbot.
Each stage is modular and independent — failures are repaired at the specific layer, not with a blind full retry.
01
Intent Extraction
Your natural language prompt is parsed into a structured intermediate form — app type, features, entities, roles, and constraints.
"Build a CRM..." → { app_type: "CRM", features: [...], roles: ["admin", "user"] }
02
System Design Layer
Intent is converted to architecture — entities, data flows, page hierarchy, role permissions, and business logic rules.
03
Schema Generation
Four schemas are generated in parallel: UI config, API config, DB schema, and Auth rules — all against strict JSON contracts.
04
Refinement + Cross-Validation
Inconsistencies across layers are detected and repaired — e.g., an API field missing from the DB schema gets added automatically.
05
Execution Readiness Check
The output is validated for executability — boot log simulation, OpenAPI stub generation, SQL migration preview.
is_executable: true → boot_log: ["✅ DB connected", "✅ Auth ready", ...]
