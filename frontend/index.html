How it works

A compiler, not a chatbot

Unlike a single prompt to an LLM, this system routes your intent through 6 specialised stages, each with its own model, validation, and repair layer.

🧠
Stage 1 — Intent Extraction
Parses your natural language description into a structured intermediate form: entities, roles, features, integrations, and assumptions for vague inputs.
openai/gpt-oss-120b
🏗
Stage 2 — System Design
Converts structured intent into a full app architecture: pages, routes, entity relationships, role permissions, business flows, and rules.
qwen/qwen3-32b
📋
Stage 3 — Schema Generation
Generates four strict schemas simultaneously: UI config, REST API config, full database schema (with foreign keys), and auth/JWT configuration.
meta-llama/llama-4-scout
🔧
Stage 4 — Refinement
Cross-validates all layers and fixes inconsistencies: missing DB columns, unregistered API routes, auth guard gaps, and role mismatches.
openai/gpt-oss-20b
🛡
Stage 5 — Validation & Repair
Structurally validates every field. If invalid JSON or missing keys are found, it repairs specific parts intelligently — no blind full retry.
llama-3.1-8b-instant
🚀
Stage 6 — Execution Check
Produces an OpenAPI stub, SQL migration preview, and a simulated boot log proving the output can power a real application.
openai/gpt-oss-120b

Getting Started

Three steps to a full app config

01
Write your app description
Use plain English. Be as detailed or vague as you want. The system makes reasonable assumptions for missing details and documents them.
e.g. “Build a CRM with login, contacts, role-based access and payments”
02
Click Compile App
The 6-stage pipeline runs in sequence. Each stage is handled by a different AI model specialised for that task. Watch the stages light up in real-time.
Average time: 15–40 seconds
03
Review and export the output
Explore each schema layer (UI, API, DB, Auth), check validation results, and see the OpenAPI stub + SQL migration preview in the Runtime tab.
All output is valid, copy-able JSON
